Pre-flight

Session

a simulation session can only take the test subject and the sim rig, so nothing simulated can land in a real animal's fluid record. every welfare check still runs, against the test subject's own bounds file.

Save directory

the folders come from the box, not from the viewer's computer: a browser's own file picker cannot name a path on another machine, and does not hand the page a path even on the box itself.

Rig

Task

a new session cannot start a run until the task library (wl-mllib, to be renamed) is pulled from GitHub; the commit is recorded with every run and goes into the code package. if GitHub cannot be reached, the last version pulled on this box runs after a warning and a person's confirmation (PI, 2026-09-26); a box that has never pulled has nothing to fall back on.

Request

how a request leaves the rig and how results come back is open: wl-works cannot be reached from a lab host, and wl-preproc's host never opens a connection. candidates: the box offers pending requests on its lab-host endpoint and wl-preproc collects them, or results are written to wl-nas and the box polls for them.

Summary

end the session? it takes no more runs, the in-session clock stops, and the code it used is packaged.

Record

Code used

the package holds the exact files every run used: wl-expcontroller, each task, the subject's bounds file, the rig's config and monitor calibration, and the environment lock, with the diff of anything not committed. it is written into the session directory and travels to wl-nas with the data (PI, 2026-09-26). pushing it to GitHub, one commit per session so git shows what changed between sessions, is proposed as wl-preproc's job, not the rig's.

Transfer to wl-nas

wl-nas does not exist yet (wl-stack, data-access.md). wl-preproc finds sessions by polling the NAS, so the rig only copies; nothing is pushed to wl-works.
