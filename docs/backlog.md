# Backlog

Every open idea and to-do for wl-xcon (the Python package `wl_xcon`), one line each. It holds only what is open: git history is the record of what closed. **The reasoning stays where it arose** (a spec, a CHECKPOINT entry, a review) and is linked, never restated here.

**Rules.**
1. **An item goes in at the moment it is deferred**, by whoever defers it: a session, a review ruling, a PI request to discuss something later.
2. **When a plan finishes, its ledger's open deferred findings and carries move here before the ledger is deleted** (`.superpowers/sdd/<plan>/progress.md` is git-ignored and dies with the plan).
3. **Closing an item removes its line**, in the commit that does the work, whose message names the ID ("closes XC-017"). IDs are never reused.
4. **Not for decisions.** A question that is the PI's to decide is asked when it arises (CLAUDE.md, "Ask, do not file"), never queued here. A brainstorm he *asked* to have later is an item; a decision nobody has put to him is not.
5. **Session start reads it**, after `docs/CHECKPOINT.md`, which points here.

**Adding one.** Take the next free ID below and raise it by one in the same commit. Write one line in the section of its kind:
`- **XC-NNN** <title, one sentence> — <date it arose, YYYY-MM-DD>, <link to where> — waits on: <what must happen first, or nothing>`
No ` — ` inside a field. Link a section, not a file, where one exists. `tests/test_backlog.py` enforces the shape.

**Finding one.** Grep the ID, a package (`P9`, `b3`), a repository (`wl-sync`) or a file. The sections: brainstorms the PI asked to have later; features no plan covers yet; defects and review findings deliberately not fixed; debt (cleanup, stale wording, test hygiene); anything that needs the rig or other hardware, measurements included; and asks of, or waits on, other repositories.
